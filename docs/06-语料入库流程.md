# 怎么把真实保险条款喂进去

> **一句话**：`python scripts/ingest.py "你的条款.pdf"` 就够了。
> 它会自动清理 PDF 里的噪声、拆好标题、写成 JSON。
> 下面解释它做了什么，以及为什么需要这些处理。

---

## 零、先理解「索引」是什么（这决定了为什么要重建）

系统里有两份东西，**很容易混淆**：

| | `data/raw/` | `data/index/` |
|---|---|---|
| 是什么 | **原始语料**（你下载/整理的条款） | **检索用的索引**（预计算的数据结构） |
| 长什么样 | `.json` / `.pdf` 文档 | `vectors.npz` + `meta.json` + `bm25.json` |
| 谁生成的 | 你放进来的 | `build_index.py` 跑出来的 |
| 进 git 吗 | 仅合成示例默认跟踪；用户语料默认忽略 | ❌ 不进（可重建的产物） |

### 为什么必须有索引

每次提问时，系统要做两件"贵"的事：

1. **把语料切成块，再把每块转成向量**（几百个块就是要调几百次 embedding）
2. **把词建成 BM25 倒排表**（统计每个词出现在哪些块、出现几次）

这两件事**跟用户的问题无关**，只跟语料有关。所以提前算好存下来，提问时直接查 —— 这就是索引。

**提问时的流程**：
```
用户问题 → 转成向量 → 在索引里找最近的块（毫秒级）
                    → 同时用 BM25 查关键词
                    → 两路结果融合 → 送进模型
```

### 什么时候必须重建索引

| 情况 | 要重建吗 | 为什么 |
|---|---|---|
| **加了新条款 / 改了语料** | ✅ **必须** | 新条款不在索引里，永远检索不到 |
| **换了 embedding 模型** | ✅ **必须** | 不同模型的向量不在同一空间，混用结果无意义（系统会直接报错，不会静默出错） |
| **改了切分参数**（`PR_MAX_CHARS` 等） | ✅ 必须 | 块边界变了，旧向量对应的是旧的块 |
| 改了提示词 / 换了 LLM | ❌ 不用 | 这影响生成，不影响索引 |
| 改了 top_k / 是否开 Rerank | ❌ 不用 | 这是检索时的参数，索引无关 |

> 记住这条：**索引是语料的函数**。语料变了或向量模型变了，就要重建。

## 二、它自动处理的四类 PDF 噪声

这四类都是**真实 PDF 抽取必然遇到**的问题。不处理，检索质量会明显下降。

### 1. 页码与页脚

```
第 1 页 共 3 页        ← 三种格式都识别
- 2 -
3 / 12
版权所有 未经许可不得翻印  ← 页脚
```

**为什么必须去掉**：这些行在每一页都出现。如果留在语料里，
每个 chunk 都会包含"共 3 页"这类高频词，**稀释掉真正的内容特征**，
让检索区分不出哪一块才是相关的。

### 2. 跨页页眉（最麻烦的一类）

```
第 1 页页眉：示例财产保险股份有限公司
第 2 页页眉：示例财产保险股份有限公司 示例e生保长期医疗险条款
第 3 页页眉：示例财产保险股份有限公司
```

**为什么最难**：各页页眉文字**不完全相同**，所以"找重复行"的办法会漏掉第 2 页那个。

**本工具的做法**：**按位置判断**，而不是按重复次数。
先让 `extract_pdf_text()` 在页与页之间插入换页符，
然后只看每页的**首行和末行** —— 这些位置出现的短行几乎必然是页眉页脚。

> 开发这里时踩了一个真实的坑：pypdf **不会**自己插入换页符，
> 而且它把 `\f` 放在**下一页第一行的开头**（`'\x0c示例财产保险股份…'`），
> 不是独立一行。所以"整行等于 `\f`"的判断永远不命中，
> 分页信息在中途就丢了，退回成了不靠谱的"按重复次数猜"。
> 这是靠 `scripts/debug_headers.py` 把中间状态打出来才定位到的。

### 3. 标题和正文挤在同一行

```
第一条 保险合同的构成 本保险合同由保险单、保险条款……共同构成。
```

如果整行被当成标题，**正文就全丢了**。工具会在全角空格或标点处把它切开：

```
标题：第一条 保险合同的构成
正文：本保险合同由保险单、保险条款……共同构成。
```

### 4. 标题被换行拆开

```
第一条 保险合同的
构成
本保险合同由保险单……
```

「构成」没有句末标点、很短，是标题的续行。工具会拼回 `第一条 保险合同的构成`。

> ⚠️ **处理顺序很关键，不能颠倒**：
> 先拆「挤在一行」→ 再拼「被换行拆开」。
> 如果反过来，第 3 类那个长行会先被拼成更长的行，
> 然后就再也拆不开了（`classify()` 会因为超过 40 字直接放弃）。
> 这个顺序错误导致过一个真实的 bug。

## 三、支持的标题格式

| 格式 | 例子 | 识别为 |
|---|---|---|
| 部分 | `第一部分 总则` | level 1 |
| 章 | `第一章 保险责任` | level 2 |
| 节 | `第一节 一般规定` | level 3 |
| 条 | `第一条 保险合同的构成` | level 3 |
| 数字编号 | `1.1 保险责任` `3.2.1 等待期` | level 4 |

**不支持**：`一、` `（一）` `1.` 这类序号当标题 —— 它们和列表项格式完全一样，无法区分。
遇到就手工改成「第X条」，或者用数字编号格式（`1.1`）重排。

## 四、自测：生成测试 PDF 练手

本机测试 PDF（3 页，含上述全部四类噪声）因体积较大被 Git 忽略。新 clone 后可在 Windows 上运行脚本生成：

```powershell
# 生成测试 PDF（依赖 Windows 中文字体）
python scripts/make_test_pdf.py

# 看 pypdf 抽出来是什么样
python scripts/debug_pdf_text.py data/samples/测试条款.pdf

# 看清洗与识别过程
python scripts/ingest.py data/samples/测试条款.pdf --dry-run

# 看中间状态（页眉检测的内部数据）
python scripts/debug_headers.py data/samples/测试条款.pdf

# 真正入库
python scripts/ingest.py data/samples/测试条款.pdf --doc-id my-test --product-name "我的测试产品"
python scripts/check_json.py data/raw/my-test.json     # 检查标题/正文是否正确分离

# 重建并提问
python scripts/build_index.py --rebuild
python scripts/cli.py products
```

需要时可重新运行 `python scripts/make_test_pdf.py` 覆盖生成。

## 五、验证与排查

### 检查入库结果

```powershell
# 看结构对不对（最重要的一步）
python scripts/check_json.py data/raw/你的doc_id.json

# 期望输出：每条都有正文
#   ✓ 每条都有正文，标题与正文分离正确
#
# 如果出现「← 没有正文！」说明标题识别把正文吃掉了，需要调整原文格式
```

```powershell
# 看切分结果
python scripts/build_index.py --rebuild --dump 3

# 期望：没有「N 个 chunk 没有识别出条款号」的警告
# 这个数字意味着有多少块无法溯源引用，最好为 0
```

### 常见报错

| 报错 | 原因 | 解决 |
|---|---|---|
| `这个 PDF 一页文本都没抽出来` | **扫描件**（整页是图片，没有文字层） | 先用 OCR 转成文本（Acrobat「识别文本」/ WPS / 截图识别），存成 txt 再跑 |
| `识别出可检索条款：0 条` | 标题格式不支持，或标题没独占一行 | 用 `--dry-run` 看它读到了什么，前 15 行会打印出来 |
| `sections 为空，没有可检索内容` | 同上 | 同上 |
| `向量模型与索引不匹配` | 换了 embedding 模型但没重建 | 加 `--rebuild` |
| `N 个 chunk 没有识别出条款号` | 有些内容不在「第X条」结构里（如开头的声明段） | 一般可接受；如果数字很大，检查原文标题格式 |

## 六、⚠️ 换完语料必须同步改的东西

**这一步不做，评测就是错的。**

| 文件 | 改什么 |
|---|---|
| `eval/testset.csv` | `expected_doc_ids`（新 doc_id）和 `expected_articles`（答案在第几条）**全部重写** |
| `data/raw/README.md` | 记录语料来源、版本、下载日期 |
| `docs/03-迭代日志.md` | 新增一节，记下真实语料的评测数字 |

### 重写测试集的正确方法

**❌ 错误做法**：用 `cli.py ask` 看系统召回了第几条，然后照着写进 CSV。
这样写出来的测试集是"照着系统表现出的"，**指标会虚高**，面试时一追问就露馅。

**✅ 正确做法**：打开条款原文，人工确定"这个问题的答案应该在第六条"，再写进 CSV。
**以条款为准，不以系统表现为准。**

## 七、索引相关的一个设计细节（面试会问）

**换 embedding 模型为什么必须重建？**

不同模型把文字映射到**不同的向量空间**。模型 A 里"等待期"和"免责条款"可能距离 0.3，
模型 B 里可能是 0.8。用模型 B 生成的查询向量，去和模型 A 生成的语料向量算相似度，
得到的分数**没有任何意义**，但程序不会报错 —— 它会安静地返回一堆垃圾结果。

所以索引文件里存了 `signature` 字段（例如 `hash-v1-dim512` 或 `local:BAAI/bge-large-zh-v1.5`）。
加载时校验，不匹配直接抛错：

```
向量模型与索引不匹配，必须重建索引：
  索引是用 'hash-v1-dim512' 建的
  当前配置是 'local:BAAI/bge-large-zh-v1.5'
原因：不同模型产出的向量不在同一空间，混用会得到无意义的结果。
重建：python scripts/build_index.py --rebuild
```

**这个设计本身是个可以讲的点** —— 它体现的是"让错误响亮地失败，而不是安静地降级"。
