# 真实保险条款获取指南

> 这份文档解决一件事：**把示例语料换成真实条款**。
> 换完之后，你的评测数字才有意义，项目才能写进简历。

---

## 一、为什么必须换（先讲清楚代价）

现在的示例语料是**我合成的**。它证明链路能跑，但不能证明任何效果。具体危害：

| 问题 | 后果 |
|---|---|
| 只有 2 个产品、21 个 chunk | top-20 召回等于"把库里大半都捞回来"，Hit Rate 必然 100% → **评测失效** |
| 答案原词直接出现在正文 | "90日""1万元"是原字匹配，连 hash 向量都能命中 → **测不出检索能力** |
| 条款结构比真实的简单 | 真实条款有交叉引用（"见第六条第二款"）、有条款附表、有定义与责任的相互引用 |
| 没有干扰项 | 检索难度被人为降低 |

**换真实语料之后**，下面这些才测得出东西：
- 切分粒度到底多少合适（E2 实验）
- 层级路径注入值多少 Hit Rate（E1 实验）
- 混合检索在什么查询上真正赢（E3 实验）

## 二、合法获取渠道（按推荐度排序）

### 🥇 1. 中国保险行业协会 · 产品信息库

**网址**：<https://www.iachina.cn> → 产品信息 / 条款费率查询
另有条款费率入口：<https://wap.iachina.cn/col/col38/>

**优点**：行业协会官方，**各公司报备条款集中可查**，一次能拿到多家公司的同类产品 —— 这对"多产品对比"类题目极其重要。
**缺点**：界面偏老，检索体验一般；部分产品只有条款摘要。

### 🥇 2. 保险公司官网 · 公开信息披露 / 产品信息专栏

这是**最稳、最完整**的来源 —— 因为《人身保险产品信息披露管理办法》要求保险公司公开披露产品条款。

| 公司 | 路径 | 备注 |
|---|---|---|
| **太平洋健康保险** | <https://cpic.com.cn> → 公开信息披露 → 产品基本信息 | 结构清晰，PDF 直接可下 |
| **平安健康 / 平安人寿** | <https://yl.pingan.com> → 公开信息披露 | 条款 PDF 直链，如 `yl.pingan.com/app_upload/file/...pdf` |
| **中国人寿** | <https://www.e-chinalife.com> → 公开信息披露 | 产品多 |
| **泰康在线 / 泰康人寿** | 官网 → 信息披露 | 互联网医疗险条款较全 |
| **众安保险** | <https://www.zhongan.com> → 公开信息披露 | 互联网保险，条款偏简洁，适合入门 |
| **人保健康 / 人保寿险** | 官网 → 公开信息披露 | — |

> **通用路径**：官网首页 → 底部或顶部导航找「**公开信息披露**」/「**信息披露**」/「**产品信息**」→ 再找「**产品条款**」/「**产品说明书**」。
> 找不到就用站内搜索，关键词：`条款` `产品信息` `信息披露`。

### 🥈 3. 各大保险经纪/第三方平台的条款库

如慧择、小雨伞、支付宝蚂蚁保的产品详情页，通常附条款 PDF 下载。
**优点**：按险种分类好找。
**缺点**：可能只覆盖在售产品，且要确认是否转载授权。**建议只作为"找到产品名"的线索，最终回到官网去下原始文件。**

### 🥉 4. 政府/监管公开文件（做政策类题目时用）

- **国家金融监督管理总局**：<https://www.nfra.gov.cn> —— 规章、规范性文件
- **国家标准全文公开系统**：<https://openstd.samr.gov.cn> —— 如果你以后转做"技术标准合规检查"方向，这是合法且免费的语料源

## 三、选哪几份条款（这一步比"下多少"重要）

**建议选 3–5 份同类产品**，理由是同类才有对比价值、题目才好出：

| 优先级 | 险种 | 为什么选它 |
|---|---|---|
| **1** | **百万医疗险 × 3 份**（不同公司） | 责任结构相似 → 适合做"多产品对比"题；等待期/免赔额/续保条件差异明显 → **对比类题目有真实区分度** |
| **2** | **重疾险 × 1–2 份** | 疾病定义列表极长（几十种疾病定义）→ **天然测试切分能力**：切太粗会丢疾病，切太细整条碎掉 |
| **3** | 意外险 × 1 份 | 责任清晰、条款短，适合当"干扰项"放进库里 |

**为什么重疾险值得单独放一份**：它的"重大疾病定义"章节通常是几十个疾病的独立定义，是**检验切分策略最好的语料** —— 比医疗险更能暴露"固定字数切分"的问题。这一条写进面试话术里很有说服力。

**不要选的**：
- 分红险/万能险（有大量利率演示表，PDF 抽出来是灾难，和 RAG 能力无关）
- 车险条款（表格多、地域差异大）

## 四、拿到 PDF 之后怎么入库

### 路线 A：直接用 PDF（快速验证）

```powershell
cd "D:\ds harness\insurance-rag"
Copy-Item "下载的条款.pdf" "data\raw\安心保百万医疗险2024.pdf"
python scripts\build_index.py --rebuild
```

系统会自动走 `load_pdf_document()`：`pypdf` 抽文本 → `sections_from_plain_text()` 用标题识别重建层级。

**但要注意三个已知问题**：
1. **扫描件抽不出文本** → 脚本会明确报错提示（不会静默产生空语料）
2. **表格会抽成错乱文本**（现金价值表、保障责任表）→ 这些块会变成噪声，检索时可能被召回
3. **页眉页脚会混进正文** → 每页重复的"第 X 页 共 Y 页"会污染段落

### 路线 B：转成 JSON（推荐，为了评测）

转 JSON 多花 1–2 小时，但换来三件事：**引用准确**、**条号可靠**、**评测集可写**。

转换时要做的最小工作：
1. 按"第X条"切成条目，每条一个 `text`
2. 补齐 `level`（部分=1 / 章=2 / 条=3）
3. **删掉页眉页脚**和"第 X 页"行
4. 把关键表格**手工补成文本**（只补你打算出题的那几张：免赔额、赔付比例、等待期）

> **面试价值**：这个"清洗语料"的过程本身就是一段好素材。
> 你可以说："我发现 PDF 直接抽出来的文本里，每页重复的页眉会污染检索结果，
> 因为它让所有块都包含同样的高频词。我加了一个页眉页脚检测去掉了它。"
> —— 这是**真实做过**才会遇到的问题。

## 五、换完之后必须同步改的东西

⚠️ **这一步漏掉，评测就是错的**：

| 要改的文件 | 改什么 |
|---|---|
| `eval/testset.csv` | `expected_doc_ids`（新语料的 doc_id）和 `expected_articles`（答案在第几条）**全部要重写** |
| `data/raw/README.md` | 记下语料来源、版本、下载日期 |
| `docs/03-迭代日志.md` | 新增一节"基线 2"，记下换成真实语料的数字 |

**测试集重写的快捷方法**：先建索引，然后用 `cli.py ask` 把你关心的问题都问一遍，看它召回的是第几条，再据此写 `expected_articles`。
**但这有个陷阱**：这样写出来的测试集是"照着系统的表现出的"，会让指标虚高。
**正确做法**：先打开条款原文，人工确定"这个问题的答案应该是第几条"，再写进 CSV —— **以条款为准，不以系统表现为准**。

## 六、语料规模的现实预期

| 语料 | chunk 数（max_chars=800） | 评测是否有意义 |
|---|---|---|
| 现在的示例（2 份合成） | 21 | ❌ 无效 |
| **2–3 份真实条款** | **150–400** | ✅ 开始有意义 |
| 5–8 份真实条款 | 400–800 | ✅✅ 推荐 |
| 10+ 份 | 1000+ | ✅✅✅ 但清洗成本高 |

**建议先做 3 份**（2 份百万医疗 + 1 份重疾），把评测跑通，拿到**第一组真实数字**。
这比一次下 20 份然后卡在清洗上要快得多。

## 七、如果一时下不到 PDF 怎么办

**别卡在这里** —— 这是新手最容易耗掉一周的坑。两个备选：

1. **只用 1 份真实条款 + 扩写合成条款**：
   以真实条款为模板，合成几份结构相似但参数不同的（等待期改成 60 天、免赔额改成 5000）。
   这样**结构是真的、参数是假的**，检索和评测都能做，但要在 README 里注明。
2. **先换真实 embedding**：
   语料不动，先把 `PR_EMB_PROVIDER` 从 `hash` 换成真实模型。
   虽然语料小，但能验证"向量检索是否真的比字形匹配强"——**这也是一组有价值的对照数据**。

> ⚠️ **绝对不要编造条款内容然后当成真实条款。**
> 面试官如果问"这条是哪个产品的"，编不下去。合成数据就说是合成的。
