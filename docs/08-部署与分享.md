# 部署与分享（本地运行 / Docker / GitHub）

> 三种方式，按你的场景选：
> | 场景 | 用哪个 | 门槛 |
> |---|---|---|
> | 自己电脑上用 | **方式一：双击 .bat** | 零门槛 |
> | 发给别人用 | **方式二：Docker** | 对方装个 Docker Desktop |
> | 放到服务器 / 云上 | **方式三：Docker + 部署文档** | 需要一台机器 |
>
> 想分享源码让人自己跑：**方式四：GitHub**（见文末）

---

## 方式一：本地一键运行（推荐先做这个）

### 第一次：双击 `安装.bat`

它会依次做四件事：
1. 检查 Python 版本（需要 3.10+）
2. 检查 Node.js（没有也能用，只是没有网页界面）
3. 装 Python 依赖
4. 装前端依赖并构建

装完还会自动生成示例语料、评测题、构建索引。

### 之后每天：双击 `启动.bat`

它会自动：
1. 检查索引在不在（不在就建）
2. 检查前端构建在不在（不在就构建）
3. 启动服务
4. **2 秒后自动打开浏览器**

**关掉那个黑窗口 = 关闭系统。**

### 手动启动（想自己控制时）

```powershell
cd "D:\ds harness\insurance-rag"
uvicorn policyrag.api:app --app-dir src --port 8000
```

## 方式二：Docker（发给别人用）

### 对方要做什么

```bash
# 1. 装 Docker Desktop（一次性）
#    https://www.docker.com/products/docker-desktop

# 2. 拿到项目，进目录并启动
docker compose up -d

# 3. 打开浏览器
#    http://localhost:8000
```

**就这三步。** 不需要装 Python、不需要装 Node、不需要 pip install。

### 用自己的条款（容器里）

把 PDF 放进 `./data/raw/`，然后：

```bash
docker compose run --rm app python scripts/ingest.py /app/data/raw/你的条款.pdf
docker compose restart app
```

或者**直接在网页上拖文件**（更简单）—— 打开 http://localhost:8000/app ，点右上角「管理语料」。模型密钥可在「模型设置」中填写，写入宿主机 `.runtime/settings.env` 并在本机生效。

### 接真实模型

本机 Docker 页面可在 `/app` 顶部「模型设置」里填写并保存 API 配置到 `.runtime/settings.env`。设置接口仅允许本机访问；服务器远程部署请在启动前创建 `.runtime/settings.env` 或直接配置服务器环境变量。

```bash
# 网页里保存配置，或远程部署时手工创建本地配置文件
mkdir -p .runtime
cat > .runtime/settings.env <<'EOF'
PR_EMB_PROVIDER=api
PR_EMB_API_BASE=https://api.siliconflow.cn/v1
PR_EMB_API_KEY=填写你的embedding密钥
PR_EMB_MODEL=BAAI/bge-m3
PR_LLM_PROVIDER=api
PR_LLM_API_BASE=https://api.deepseek.com/v1
PR_LLM_API_KEY=填写你的LLM密钥
PR_LLM_MODEL=deepseek-chat
EOF

docker compose up -d --force-recreate
docker compose exec app python scripts/build_index.py --rebuild
```

> ⚠️ **密钥放在 `.runtime/settings.env` 里，它已经在 `.gitignore` 中，不会被提交。**
> 千万不要把密钥写进 `.env.example`、`docker-compose.yml` 或任何会提交的文件。

### 换 embedding 模型后必须重建

```bash
docker compose exec app python scripts/build_index.py --rebuild
```

不同模型的向量不在同一空间。不重建的话，程序会**直接报错**（而不是安静返回垃圾结果）。

## 方式三：部署到服务器

### 需要什么

| 项 | 最低 | 说明 |
|---|---|---|
| 系统 | 任意 Linux | Ubuntu 22.04 测过 |
| Docker | 20.10+ | 用官方脚本装 |
| 内存 | 2 GB | 用 API embedding 的话 1 GB 也够 |
| **GPU** | **不需要** | 本项目不训练模型，除非你要本地跑大模型 |
| 磁盘 | 10 GB | 镜像约 1.5 GB |

### 部署步骤

```bash
# 1. 装 Docker
curl -fsSL https://get.docker.com | sh

# 2. 拿代码
git clone https://github.com/你的用户名/insurance-rag.git
cd insurance-rag

# 3. 配置密钥
cp .env.example .env
vim .env

# 4. 起服务
docker compose up -d

# 5. 看日志
docker compose logs -f
```

### 加 HTTPS 反代（生产必须）

```nginx
server {
    listen 443 ssl http2;
    server_name your-domain.com;

    ssl_certificate     /path/to/cert.pem;
    ssl_certificate_key /path/to/key.pem;

    location / {
        proxy_pass http://127.0.0.1:8000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;

        # ⚠️ SSE 流式必须这三行，否则打字机效果会消失
        proxy_buffering off;
        proxy_cache off;
        proxy_read_timeout 300s;
    }
}
```

> **这三行是踩过坑的**：后端已经设了 `X-Accel-Buffering: no`，
> 但 nginx 是双重保险。只靠后端那个头在某些 nginx 配置下仍会被缓冲，
> 表现就是"回答要等好几秒才一次性出现"，而不是逐字出现。

### 用 GitHub Actions 自动构建镜像

`.github/workflows/docker.yml` 已经写好：

- PR / 推送到 `main` → 只构建镜像，检查构建是否正常
- 打 tag（如 `v1.0.0`）→ 构建并推送版本镜像到 `ghcr.io`
- Actions 手动触发 → 只构建，不推送镜像

**别人可以直接用构建好的镜像**：

```bash
docker run -d -p 8000:8000 \
  -v $(pwd)/data:/app/data \
  -e PR_LLM_API_KEY=sk-... \
  ghcr.io/你的用户名/insurance-rag:latest
```

> 用 `ghcr.io` 而不是 Docker Hub 的原因：ghcr 用仓库自带的 `GITHUB_TOKEN` 就能推，
> **不需要额外配置任何密钥**。想换 Docker Hub 的话，
> 在仓库 Settings → Secrets 里加 `DOCKERHUB_USERNAME` 和 `DOCKERHUB_TOKEN`。

## 方式四：推到 GitHub

### 第一次推送

```powershell
cd "D:\ds harness\insurance-rag"

# 仓库已在本机初始化；先审阅将提交的文件
git status --short
git add .
git diff --cached
git commit -m "feat: 保险条款 RAG —— 层次感知切分 + 混合检索 + 30题评测集"

# 去 github.com 新建一个空仓库（不要勾 README / .gitignore）
git remote add origin https://github.com/你的用户名/insurance-rag.git
git branch -M main
git push -u origin main
```

### ⚠️ 推送前必须确认的三件事

| 检查项 | 命令 | 期望 |
|---|---|---|
| **没有密钥泄露** | `git status` 和 `git diff --cached` | 确认没有真实 API key、token 或密码 |
| `.env` 没被提交 | `git ls-files \| findstr ".env"` | 只应看到 `.env.example` |
| 大文件没进去 | `git ls-files data/samples/` | 输出中不应有 `测试条款.pdf` |

**万一密钥已经提交了**：
1. **立刻去服务商后台吊销那个 key**（这是唯一有效的补救）
2. 然后才去清理 git 历史（`git filter-repo` 或 BFG）
3. 只删文件不吊销密钥 = 密钥仍然泄露

### 仓库里应该有什么、不该有什么

| 应该进 | 不该进 |
|---|---|
| `src/` `scripts/` `web/src/` `tests/` | `.env`（密钥） |
| `docs/` 全部文档 | `node_modules/`（2 万多个文件） |
| `eval/testset.csv`（评测题） | `web/dist/`（构建产物） |
| `data/raw/sample-*.json`（合成示例） | 用户真实条款、`.env`、`data/index/`、`eval/results/` |
| 测试 PDF 生成脚本 | `data/samples/测试条款.pdf`（可重新生成） |
| `Dockerfile` `docker-compose.yml` `.env.example` | `*.log` |
| `安装.bat` `启动.bat` | 大 PDF（超过 50 MB 的） |

`.gitignore` 会保留 `sample-*.json` 合成示例，并忽略其他 `data/raw/` 内容（包括真实条款 JSON/PDF）。如果你确认拥有分发权且希望公开某个语料，应先单独确认许可，再调整忽略规则。

### README 要写什么（给别人的第一印象）

一份能被别人跑起来的 README 只需要回答四个问题：

1. **这是什么** → 一句话 + 一张截图
2. **怎么跑起来** → 三条命令（越少越好）
3. **我需要准备什么** → Python 版本、要不要 API Key
4. **已知限制** → 诚实写清楚（本项目这一节写得比较长，是故意的）

本项目 README 已经按这个结构写好了。

## 常见问题

| 现象 | 原因 | 解决 |
|---|---|---|
| `安装.bat` 说找不到 python | 没装或没加 PATH | 装 Python 时勾选 "Add Python to PATH" |
| 双击 bat 闪一下就没了 | 出错了但窗口关了 | 右键 bat → 用 PowerShell 打开，或在 cmd 里手动跑 |
| 浏览器打不开 | 服务没起来 | 看那个黑窗口有没有报错 |
| 页面显示「索引未就绪」 | **后端没在跑**（不是索引问题） | 重新双击 `启动.bat` |
| Docker 里问不出东西 | 索引没建 | `docker compose exec app python scripts/build_index.py --rebuild` |
| nginx 下没有打字机效果 | 代理在缓冲 | 加 `proxy_buffering off;` |
| 容器起来但页面空白 | 前端没构建进镜像 | 确认 `docker build` 时用了多阶段（本项目 Dockerfile 已配） |

## 一个必须说清楚的事

**本项目默认配置不能用于真实业务。**

| 默认值 | 问题 |
|---|---|
| `PR_EMB_PROVIDER=hash` | 字符哈希，**不是语义向量**，检索效果差 |
| `PR_LLM_PROVIDER=mock` | 不调真实模型，返回占位文本 |
| 仓库自带 `data/raw/sample-*.json` | **合成的示例条款**，不是任何真实产品；本机真实条款不会随仓库分发 |

**要用在真事上，必须做三件事**：
1. 换成真实条款语料
2. 换真实 embedding 模型
3. 换真实 LLM

而且即使全换完，**这也是一个技术演示项目，不是经过合规审查的核保系统**。
拿它给客户下理赔结论之前，请让法务和精算看一遍。
